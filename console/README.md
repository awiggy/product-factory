# 产品工厂控制台

一个在你电脑上运行的网页界面，用来推进产品：回答 AI 的问题、勾选待办、照清单验收、盖章审批、进入下一阶段，都是点按钮完成，不需要在对话里来回说。

## 启动

- **双击** 仓库根目录的 `启动控制台.command`（第一次可能需要右键 → 打开，允许运行）。
- 或者在终端运行：`python3 console/server.py`

浏览器会自动打开 `http://localhost:8765`。关闭终端窗口即停止。只需要 Python 3.9+，不用安装任何依赖。

## AI 执行方式（在“设置”里选）

控制台负责流程、闸门和审批，具体的活交给你电脑上的 AI 命令行工具。设置页会自动扫描本机装了哪些 AI 命令行工具，检测是否登录，并列出可选模型；模型选“默认”时使用该工具自己设置里的默认模型。

| 方式 | 凭据 | 说明 |
| --- | --- | --- |
| Claude Code + Claude 账号 | 在终端运行 `claude` 登录 | 推荐。按阶段细分权限：需求、架构、选型阶段只能读写文件 |
| Claude Code + 国内或第三方模型 | 厂商的 API Key | DeepSeek、Kimi、智谱 GLM、MiniMax 或任何 Claude 兼容接口。不需要 Claude 账号。费用以厂商账单为准，控制台显示 token 用量 |
| Codex + ChatGPT 账号 | 在终端运行 `codex` 登录 | 在沙箱里工作：只能改产品文件夹，开发、评测、上线阶段才联网 |
| Codex + OpenAI API Key | OpenAI API Key | 同上，按调用量付费 |
| pi | 在 pi 里 `/login`，或配置厂商 API Key | 可选 pi 支持的任意厂商模型（下拉列表来自 `pi --list-models`）。没有沙箱，控制台用工具白名单限制：需求、架构、选型阶段不能运行命令 |
| 演示模式 | 无 | 用示例内容走完 8 个阶段，不调用 AI |
| 其他 AI 工具（高级） | 无 | 只有 Gemini CLI、OpenCode 等暂未接入的工具时的兜底：控制台照常管理流程，只是每一步要把指令复制给别的 AI 助手执行 |

API Key 保存在 macOS 钥匙串（其他系统保存在 `~/.config/product-factory/secrets.json`，权限 600），不会写进项目文件，也不会回传到网页。运行时只通过环境变量交给对应的命令行工具。“保存并测试连接”会实际调用一次模型，确认 Key、地址和模型名都可用。

Codex 模型下拉优先读取官方 `codex app-server` 的 `model/list`，点击“重新检测”会重新读取目录，不创建对话或执行模型推理。查询沿用本机 Codex 登录与配置，不用工厂保存的 API Key 发起登录。读取失败时可显示 `CODEX_HOME`（默认 `~/.codex`）下 `models_cache.json` 的可显示模型，并标明缓存来源与时间；自定义 Codex provider、默认 profile 或自定义目录配置不回退到 OpenAI 缓存。目录可能来自 Codex 内置目录，不保证当前账号或 API Key 的调用权限，仍可选“默认”或“其他（手动填写）”。详见 [模型列表协议](https://developers.openai.com/codex/app-server#list-models-modellist)和 [目录与访问权限的区别](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server)。

首页的“先看看演示产品”始终使用演示模式，不受设置影响。

```text
┌ 生产线：需求 ─ 架构 ─ 选型 ─ MVP ─ 前端 ─ 评测 ─ 上线 ─ 迭代 ┐
├──────────────────────────────────────┬──────────────────┤
│ 这一步做什么 / 你要做 / 会得到       │ 质检单            │
│ AI 说：……                            │  成熟度           │

│ │ 回答问题 / 勾选待办 / 照清单验收 │    │  阻塞             │

│ └──────────────────────────────┘    │  运行记录与费用   │
│ 本阶段文档                            │                  │
└──────────────────────────────────────┴──────────────────┘
```

## 验收时一键启动产品

到了需要你亲手验收的阶段，页面上方会出现“启动产品”。控制台在产品文件夹里运行产品自己的启动脚本（通常是 `./start.sh`），页面能访问后显示“打开页面”，还可以重启、停止、查看运行日志。只运行产品文件夹里的脚本、只接受本机地址；AI 开始工作前、关掉控制台时会自动停止。

旁边的“修改配置”可以随时改产品的 `.env`（保密项不显示原值），改完点“保存并重启产品”。验收清单里提到的日志等文件会有“查看”按钮；文件里如果出现了 `.env` 保密项的真实值，会打码显示并提示泄露。

## 它怎么和 AI 配合

AI 以非交互方式运行，不能和你对话。它把要问你的问题、要你本人做的事、验收清单、审批摘要写进产品文件夹的 `factory/inbox/<阶段>.json`（格式见 [收件箱协议](../skills/product-factory/references/inbox-protocol.md)），控制台把这些变成表单和按钮。你的回答会在下一次运行时交给 AI。

## 安全保护

- 只监听本机（127.0.0.1），并校验请求来源。
- 状态文件 `factory/state.json` 只能由控制台修改：AI 运行前后会比对，被改动就恢复；AI 自己写的审批会被撤销。
- 签字只能由你在界面上完成，并保存你的原话；有“未验证”或“新增费用”时必须先展开查看。
- AI 报告的证据不能超过本阶段等级；未授权部署时不接受“线上验证”证据。
- Claude Code 按阶段限制权限：需求、架构、选型阶段只能读写文件；开发阶段可运行命令（可在设置中关闭）；部署只在你授权后进行。`sudo`、`git push` 等命令始终被拦截。单次运行有费用和时长上限。

## 数据放在哪

- 产品：默认在仓库的 `products/` 下，每个产品一个文件夹（已初始化 git）。可在设置里修改。
- 控制台配置：`console/data/config.json`（产品列表、执行方式）。
- 每次 AI 运行的记录：产品文件夹的 `factory/runs/`（已在产品的 .gitignore 中忽略）。

## 测试

```sh
cd console && python3 -m unittest discover -s tests
```
