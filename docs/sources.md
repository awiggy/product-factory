## 对 B 的修订（有意改变的地方）

| B 的原做法 | 问题 | 本包的做法 |
| --- | --- | --- |
| 数据持久化默认用 `/tmp` SQLite + 预留实例 + 定时备份 + 启动恢复 | 实例更换、发布、扩容都会丢数据；两次备份之间的写入会丢；运行中复制 SQLite 文件可能不一致；多实例时数据分裂 | 只允许用于受限演示并写明丢失窗口；正式上线用托管数据库，或确认持久挂载 + 单实例 + 一致性备份 |
| 子账号逐项开 FullAccess | 权限过大 | 先列实际用到的服务，优先细粒度策略，按报错补最小权限，上线后收回 |
| 用户把 AK/SK 交给 AI，`vefaas login --accessKey ... --secretKey ...` | 密钥进入对话、命令历史 | 用户在自己终端登录 CLI，或配置进平台密钥管理；AI 不接收、不回显 |
| “判断上线成没成，只看网址能不能打开” | 可能是旧版本，或首页正常而业务接口失败 | 核对线上版本 + 真实业务流程 + 权限隔离 + 重启后数据仍在 |
| 验证阶段关闭网关可观测性开关以省钱 | 正式上线后无法排错 | 验证阶段可以关，正式上线前重新评估 |
| 前后端默认作为两个独立应用部署 | 不是所有平台和产品都需要 | 由平台与需求决定，不默认拆分 |
| BLUEPRINT 要求“无论如何都画 7 层架构图” | 小工具会被迫制造复杂度 | 七层作为检查视角，小方案可合并层级 |
| 三本手册里固定的 CLI 命令与版本 | 会过期 | 保留为“课程记录”，执行前按官方文档与 CLI 帮助核对，并记录核对日期 |

## 对 A 的补充

| A 的缺口 | 补充 |
| --- | --- |
| 不给默认技术栈（每次都要适配） | 新项目直接采用默认栈，已有项目仍然沿用现状 |
| 四个 Skill 不衔接，没有阶段状态 | product-factory + factory_gate.py |
| 没有 PRD 生成 | prd-author |
| 没有独立的 QA/效果评测阶段 | qa-eval |
| 没有上线后的迭代闭环 | operate 阶段 + iterate 命令 + PRD 变更模式 |
| 部署完全不含平台知识 | 平台适配器（veFaaS）+ 适配器模板 |
| 验证只有离线审查 | 增加脚本与端到端测试（仍未在真实产品上试跑） |
