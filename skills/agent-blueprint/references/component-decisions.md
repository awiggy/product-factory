# 需求驱动组件选型

下面的 s01–s17 是机制索引，不是本包可执行模块或路径。本 Skill 不附带这 17 套代码。课程仓库 agent-blueprint 中有对应的参考实现（每个机制一个 code.py），落地时可以对照，但要先审查依赖、许可证与安全边界，不直接复制进产品。

**默认答案是“只要循环 + 工具”。** 对每个候选组件问“没有它产品会怎样”：没变化就删；会失败就保留；不确定就标待确认。

| 机制 | 何时需要 | 设计时必须说清 | 实现要点 |
| --- | --- | --- | --- |
| s01 Agent Loop | 根据结果动态选择动作 | 停止条件、步数/时间/费用上限、工具结果配对 | 完整处理 stop_reason；超时与有限重试 |
| s02 工具系统 | 访问业务能力或外部系统 | 参数/结果契约、身份、错误、副作用和幂等 | 严格 JSON schema；错误以统一格式回传给模型 |
| s03 权限系统 | 动作有权限或风险边界 | 实际执行层鉴权、默认拒绝、审批有效期 | 破坏性操作二次确认；审计日志；失败关闭 |
| s04 Hooks | 多处需要审计/拦截/观测 | 安全拦截异常时拒绝；普通观测故障可降级 | PreToolUse 可阻断，PostToolUse 只观察 |
| s05 任务规划 | 多步任务需向用户呈现进度 | 计划与实际执行状态分别存储，不以计划完成冒充业务成功 | 计划持久化、状态可查询 |
| s06 子 Agent | 可独立验收的子任务适合隔离上下文 | 工具权限、最小输入、回传证据、并发/递归上限 | 独立消息列表；只回传结论与证据；超时回收 |
| s07 Skill 加载 | 领域知识只在部分任务使用 | 先目录后正文，来源/版本明确，文本不提升权限 | 目录先行、正文按需加载 |
| s08 上下文压缩 | 长历史挤占可用上下文 | 保留用户目标、边界、未决项和工具调用/结果配对 | 先裁工具结果，再摘要历史 |
| s09 记忆 | 跨会话确需复用信息 | 用户可纠正/删除，来源/时效/作用域，不存明文密钥 | 筛选→提取→整合；冲突时用户指令优先 |
| s10 任务系统 | 需持久化任务、依赖与续跑 | 原子状态迁移、重复事件和恢复一致性 | 依赖校验、并发锁 |
| s11 后台任务 | 慢任务不能阻塞前台 | 任务 ID、执行与连接状态分离、取消与超时语义 | 完成通知注入、超时清理 |
| s12 定时调度 | 用户明确需要未来/重复运行 | 时区、幂等、错过触发策略、停用与授权有效范围 | 调度持久化 |
| s13 Agent 团队 | 多任务并行有实际收益 | 工作区/数据隔离、领取与冲突、资源预算、关停 | 原子认领、任务绑定独立工作区、类型化消息 |
| s14 MCP 接入 | 需要现有外部工具协议生态 | 服务来源、工具范围、身份、连接降级和版本 | 命名空间（mcp__server__tool）、连接失败降级 |
| s15 集成 Harness | 多种机制需共同管理状态 | 状态所有权、统一调用边界，不强制单体或重复循环 | 共享客户端；系统提示词按状态重建 |
| s16 工作流运行时 | 编排形态固定 | 检查点、重放、幂等与人工节点；固定流程不是反模式 | 脚本拥有编排；journal 断点续跑 |
| s17 目标闭环 | 停止前需额外验证交付 | 可观测的完成证据、评估预算、不可完成时交还控制 | 独立判断器；目标不可能或超限时交还用户 |

为每个选中组件注明需求出处和更简单替代。未选的组件只需解释关键取舍，不能为了凑齐 17 项建立空模块。多 Agent 不是默认方案；架构中提出团队能力也不等于本次授权启动团队。

## 七层视角

交互、产品业务、Agent 编排、模型、能力集成、数据、基础设施用于检查职责是否遗漏。安全与观测贯穿各层，不是画两个框就完成。

复杂系统可按七层画图并标真实模块；小工具可以合并层级或使用简短数据流。每条边解释传什么数据、以谁的权限、失败在哪里处理，不为了图好看创造不存在的微服务。

## 工具契约最少字段

名称、用途、输入 schema、输出/错误、数据来源、执行身份、读/写及外部副作用、授权/确认要求、超时、重试与幂等策略、完成证据。提示词可描述规则，但执行端必须验证。
