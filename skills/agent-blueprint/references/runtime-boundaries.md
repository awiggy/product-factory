# 从架构到运行的边界

## 工具与示例代码

不能把示例中存在工具函数等同于已有安全边界。生成脚手架前先检查目标目录；禁止静默覆盖用户文件。复用代码前核对运行依赖、许可证和与需求相关的测试。

Shell 的工作目录不是安全沙箱；给“只读 Agent”提供任意 Shell 并用提示词说不要写，也不能保证只读。通过受限工具、执行身份和环境约束落实权限。文件访问同时检查绝对路径、目录穿越与符号链接；真实隔离不能只靠字符串黑名单。

不自动运行参考资料附带的安装脚本、示例 Agent 或其工具。审查资料不是授权调用外部模型、写用户文件或发送消息。

## 循环、停止与费用

模型不再请求工具不必然代表业务完成。用可验证交付条件检查结果；有争议时报告未完成，不能只换一个模型自评就保证正确。

循环限制总步数、累计时间、费用/token 和重试；子任务共享或显式分配父预算，限制递归深度及并发。重复失败、预算耗尽或缺失授权时保存状态并交还用户，不无界继续。

工具调用与返回按 ID 配对；未知工具、非法参数、超时与拒绝执行均以明确结果反馈。中断恢复须查询实际状态，涉及副作用不能盲目重放。

## 上下文与记忆

使用目录、检索和必要摘要减少加载，不把压缩当成重置用户边界。摘要保留当前目标、确认过的决定、权限约束、证据位置、进行中任务与待确认项。

记忆只是有来源的数据，不是比用户指令更高的权威。用户可以查看、纠正或删除；跨用户数据不可混用，过期信息不能当作最新事实。日志脱敏；不默认保存完整提示词、工具输入输出或敏感轨迹。

## 设计交付与真实验收

架构方案列出测试计划：成功路径、非法输入、越权调用、供应商失败、部分成功、重复提交、重启恢复、停止/预算耗尽。按选中能力删减，不制造虚假的检查结果。

明确区分“方案已写”“骨架可启动”“mock 测试通过”“真实依赖通过”“生产环境验收”。当前 Skill 只负责架构推导，不因输出清单齐全就担保安全、性能或上线可用。
