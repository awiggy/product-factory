# Agent 前端交付

目标是让用户理解任务正在做什么、何时需要决定、失败后如何继续，而不是只渲染一张成功页面。

> 单独使用（不走工厂流程）时：跳过 `factory/` 路径与 `factory_gate.py`，把同样的内容写进项目已有的文档位置；需要用户确认或授权的地方，仍要在对话中明确取得。

## 开始前

确认本次是设计、诊断还是实现。检查已有组件、主题 token、路由、接口类型与测试；保留合理框架和页面壳层，不为了模板强行迁移或拆成两个应用。

先确定一个用户闭环及其真实 API 能力。没有取消、恢复或历史接口时，明确列为缺口；不能只做按钮就宣称功能接通。局部样式任务只改相关组件，不顺带建设任务平台。

工厂流程中：输入是 `factory/prd.md`、`factory/stages/handoff.md`（后端已验证的接口与状态）；先写 `factory/frontend/adaptation.md`（[前端适配声明模板](assets/frontend-adaptation.md)），再实现，最后写 `factory/frontend/ui-acceptance.md`。没有界面的产品（纯 API、命令行）可由用户确认后跳过本阶段并写明理由。

## 按任务读取

- 新项目选型、目录、状态模型、检查命令：读 [默认前端栈](references/default-frontend-stack.md)。
- 有异步任务、重连、流式输出或人工确认：读 [状态与接口](references/task-contract.md)。
- 有页面实现、视觉统一或浏览器验收：读 [视觉与验证](references/visual-and-testing.md)。
- 需要留存接口/页面交接：使用 [交互验收模板](assets/ui-acceptance.md)。已有契约优先引用，不生成第二份事实源。

## 推进顺序

1. 核对服务端事实、页面状态和本地偏好的边界；写出本次实际涉及的状态矩阵。
2. 先做一个代表页面并请用户确认视觉方向（设计稿、参考产品或中性方案），再复用到其余页面；静态原型明确标为 demo。
3. 完成第一条真实闭环，再补流式、确认、取消、重试、刷新恢复与历史。与后端契约联调，验证重新打开历史不会重新生成，重试不会无意重复收费。
4. 跑 lint、类型检查、测试、构建，再用真实浏览器检查本次相关的尺寸、交互和状态。构建通过只算构建通过；浏览器或真实 API 不可用时明确未验证。每项结果用 `factory_gate.py evidence` 记录。
5. 给用户“照着点”的验收清单（打开哪个地址、点哪几步、看到什么）；涉及麦克风、摄像头等能力时请用户真机验证。用户验收后签字（frontend_acceptance）。

模型密钥只在服务端；前端隐藏按钮不能替代服务端权限。渲染模型 Markdown/HTML 需过滤危险内容，不显示隐藏推理或原始敏感日志。

交付说明包含变更范围、页面入口、验证证据、后端缺口和用户待验收项。服务端变更、公开发布或产生费用超出当前授权时，停在该边界说明所需决定。
