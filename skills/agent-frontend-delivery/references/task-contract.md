# 任务状态与接口契约

## 三类状态不要混存

- 服务端事实：任务状态、权限、结果、确认是否已消费、产物版本。
- 可分享/恢复的导航状态：当前 task ID、选中的报告等，可放路由但不可在 URL 放敏感信息。
- 临时 UI/偏好：侧栏展开、草稿、主题。只持久化必要内容并遵守项目隐私约束。

先查询 task ID 的权威快照，再订阅事件。事件应有可去重/排序标识或状态版本；后到的旧事件不能把 succeeded 改回 running。断线重连先重新查询；服务端没有重放能力时不用前端假装可无损补流。

## 关键情境

| 情境 | 页面行为 | 后端要求或缺口 |
| --- | --- | --- |
| 初次加载 | 显示加载，不提前显示“无记录” | 区分查询失败与空列表 |
| 已提交尚未得到响应 | 保留 pending 状态，不自动创建第二单 | 请求幂等键/原任务查询；无此能力先提示结果未知 |
| 等待用户确认 | 显示将执行的动作、影响、确认/拒绝 | 核验权限、确认版本及一次性消费 |
| 流断开 | 保留已有输出，标明连接状态 | 查询权威任务状态后恢复 |
| 取消请求 | 显示“正在取消”，直到服务器确认 | 支持取消并说明已发生副作用不能撤回 |
| 部分成功 | 保留成功产物，标明失败部分 | 支持范围明确的重试；不重复整批付费任务 |
| 刷新或打开历史 | 根据 ID 读取同一任务/结果 | 读取接口与生成接口分离，检查归属 |

双击防抖只能防本页误触，不能替代服务端幂等。仅在契约支持且安全时自动重试；否则提供明确人工操作和风险提示。

## 最小契约

复用已有字段名，不强制接口重命名。确认 task ID、状态、结果/产物 ID、错误 code、可否重试、状态版本、时间与权限语义。人工确认还要包含动作摘要、过期条件和确认凭据的服务端验证规则。

SSE/fetch 流适合单向进度与文本；轮询适合简单状态查询；只有真正双向实时需要才采用 WebSocket。对传输格式与断线恢复做契约测试，不因技术偏好更换协议。

语音/媒体任务额外处理权限拒绝、设备不可用、录制/上传/处理分段、产物 URL 过期及播放失败；不把已录制等同于已上传或已处理成功。
