# 视觉一致性与实际验收

## 一套壳层

导航、功能切换、内容最大宽度、顶部偏移与滚动容器共用布局约束。不要依赖每页按钮数量计算导航位置，也不要逐页追加负 margin 修正根因。

使用项目 token 统一字体层级、留白、密度、圆角、边框、前景/背景和状态色。正文可读性优先；不能留下旧亮色卡片配浅文字。品牌名、术语、按钮动作和图标保持统一语言。

空状态、加载、结果和历史使用同一布局系统，不能从空状态切到结果就换整套设计。示例内容与真实结果显式区分。加载、空数据、失败、无权限、记录不存在分别设计；禁用需说明原因，错误保留用户输入。

## 操作可靠性

- 表单字段有标签、验证和错误关联；默认值必须属于合法选项。
- 键盘可操作；对话框管理焦点、关闭后归还焦点；长弹窗可滚动且按钮可达。
- 流式更新使用适度的可访问提示，避免每个 token 都打断读屏。
- 响应式布局重排内容而非整体缩小；动画尊重减少动态效果偏好。
- 客户端过滤恶意渲染内容；工具日志只展示适合用户阅读的摘要和必要证据。

## 测试矩阵

按改动范围运行 lint/类型检查/构建、组件与契约测试，然后浏览器交互验证。没有这些现成命令时说明缺口，不假称执行。

可用 390、768、1280、1440 像素作为起始视口；根据目标设备与故障截图调整，不固定为所有项目硬指标。重点检查横向溢出、导航偏移、不可见按钮、弹窗滚动、焦点、文字对比及长内容。

任务型页面测试至少覆盖本次相关的成功、失败、断线/刷新、确认拒绝、重复提交与历史读取。用明确的 mock 案例覆盖难复现状态，再做获授权的真实 API 闭环。

保存必要的截图、操作和结果索引，不上传真实用户资料。交付区分“样式完成”“mock 交互通过”“真实接口通过”“用户已验收”；这些状态不可互相替代。
