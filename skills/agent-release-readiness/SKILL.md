# 发布准备与验证

先分清用户要“评估”“准备变更”还是“部署”。已有“先别上云”等约束继续有效。读取手册或本 Skill 不构成开通服务、付费、公开数据或切换生产流量的授权。

> 单独使用（不走工厂流程）时：跳过 `factory/` 路径与 `factory_gate.py`，把同样的内容写进项目已有的文档位置；需要用户确认或授权的地方，仍要在对话中明确取得。

工厂流程中：输入是 `factory/eval/report.md`（无 blocker）与各阶段交接；产出 `factory/release/record.md`。执行任何云操作前运行 `factory_gate.py require <仓库> --id release_go`，未通过就停在操作之前，向用户给出授权请求（平台/账号/环境、预计费用量级与计费方式、公开范围、数据迁移、回滚方式）。

## 最小流程

1. 确认目标环境、现有部署方式、版本、用户访问范围、持久数据和预算约束。只读查看配置名称与必要状态，不输出密钥值。
2. 上线评估或发布前读 [发布门槛](references/release-gates.md)，列出通过、阻塞、未验证、不适用，并给证据。只要求评估时到此交付，不改云资源。
3. 涉及持久数据、备份、迁移或回滚时读 [数据与恢复](references/data-and-rollback.md)。阻塞项解决前不宣称可上线。
4. 执行已授权部署前读 [平台执行边界](references/provider-execution.md)，再读目标平台的适配器：
   - 火山引擎函数服务：[veFaaS 适配器](references/platform-volcengine-vefaas.md)
   - 其他平台：按 [适配器模板](references/platform-adapter-template.md) 先整理当时官方文档的要点，再执行。
   使用目标平台当前官方文档及可用的专用工具；没有工具时说明，不编造已部署结果。
5. 验证部署版本与核心业务，不以 URL 返回 200 作为成功依据。用 `factory_gate.py evidence --level production_verified` 只记录在目标环境实际验证过的项。保留日志/检查证据，交付 [发布记录](assets/release-record.md)，并给用户上线验收清单，用户验收后签字（launch_acceptance）。

## 核心约束

- 沿用合理的部署形态；不强制前后端分成两套服务，不默认任何厂商。
- 凭据经环境或密钥管理设施提供：用户在本机终端自行登录平台 CLI，或把凭据配置进平台密钥管理；不让用户把 AccessKey、数据库密码粘进对话。使用最小必要权限，不默认多项 FullAccess。
- 预留实例或定时备份不能代替可靠持久化；临时磁盘不能作为唯一事实源。
- 服务公开前核验鉴权、授权与数据隔离。真正无需身份的公开静态内容可标不适用并说明理由。
- 发布请求不自动授权不可逆删库、破坏性迁移或额外付费扩容；目标与影响未确定时停在具体操作之前。
- 部署失败先核对实际版本与资源状态；限制重试，避免重复创建计费资源。一次有证据的修正后若同一外部阻塞仍在，报告原因与所需决定，不循环创建。

结果应能回答：上线的是哪一版、哪些路径已真实验证、数据如何恢复、如何回滚、哪些风险仍由用户决定。未实际演练的恢复或回滚只能写“方案已准备”。
