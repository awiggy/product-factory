# 平台适配器：火山引擎 veFaaS

> 来源：课程《AI Agent 产品上线部署手册 V1.1》的实战记录，按本 Skill 的安全与数据规则修订。
> 命令、参数、权限策略名、价格与开放范围会变化：执行前用 `vefaas --help`、官方文档和官方 veFaaS Skill（`vefaas skills update`）核对，并在发布记录中写核对日期。本文件不是官方文档。

## 适用场景

没有公司基础设施、需要快速得到 HTTPS 访问地址的 Web/API 产品。函数服务的实例会扩缩容，本地磁盘只有 `/tmp` 可写且是临时的，这决定了数据方案（见下）。

## 用户必须本人做的事

| 事项 | 说明 |
| --- | --- |
| 注册与实名 | AI 无法代办。注意：部分托管数据库产品可能只对企业认证开放，以控制台当时提示为准 |
| 创建专用子账号与权限 | 为本产品建子账号，只授予用到的服务；先给 AI 一份“开哪些”清单 |
| 登录 CLI | 用户在自己的终端运行 `vefaas login`，自行输入 AK/SK；AI 不接收、不回显密钥 |
| 控制台点选 | 创建网关等，AI 给“照着点”清单，用户截图反馈 |
| 确认费用 | 网关、预留实例、数据库、对象存储的计费方式和量级 |

### 权限：从最小开始

课程版本建议给多项 FullAccess，这里改为：

1. 先列出本次真正用到的服务（通常是函数服务、API 网关、对象存储；用托管数据库时再加数据库与私有网络；查日志加日志服务）。
2. 优先选择服务内的“开发/运维”类策略或自定义策略，限制到本产品的资源；只有官方没有更细粒度策略时，才对单个服务用 FullAccess，并在发布记录中写明原因与收回计划。
3. 遇到 `AccessDenied`，读报错中的 action 与资源，只补缺失的那一项。
4. 上线后收回部署期临时权限；AK/SK 定期轮换。

## 数据方案（与课程版本的关键差异）

课程版本的默认轻量方案是：SQLite 放 `/tmp` + 设预留实例常驻 + 定时把数据库文件备份到对象存储 + 启动时自动恢复。这个方案只能用于**受限演示**，不能作为有真实用户数据的正式上线方案，原因：

- 预留实例只降低被回收的概率，实例故障、发布新版本、扩容都可能换实例，`/tmp` 数据随之丢失。
- 两次备份之间写入的数据会丢；运行中直接复制 SQLite 文件（尤其 WAL 模式）可能得到不一致的备份。
- 扩到多个实例时，各实例各有一份数据库，数据分裂；启动恢复可能用旧备份覆盖新数据。

正式上线的选择（由用户在 release_go 时确认）：

| 方案 | 适用 | 说明 |
| --- | --- | --- |
| 托管关系数据库（如 PostgreSQL / MySQL） | 有账户、多用户数据、需要可靠持久化 | 首选。确认账号类型能否开通、私有网络配置、备份与恢复能力 |
| 持久化存储挂载 + 单实例 SQLite | 低并发、单写入 | 只有在平台提供真正持久的挂载且能限制为单实例时才考虑；仍需一致性备份 |
| `/tmp` SQLite + 预留实例 + 定时备份 | 受限 demo、可接受丢数据 | 在发布记录写明“数据可能丢失，丢失窗口 = 备份间隔 + 实例更换”，并告知用户；不用于正式用户 |

文件产物（音频、图片、文档）一律放对象存储私有桶，下载走鉴权或短期签名。

## 部署流程要点

1. **自检**：在后端目录运行 `vefaas inspect`。入口不在根目录时框架可能识别失败，显式指定启动命令，例如 `python -m uvicorn app.main:app --host 0.0.0.0 --port 8000`（用 `python -m` 避免 `uvicorn: command not found`）。
2. **排除文件**：维护 `.gitignore` 与 `.vefaasignore`，排除 `.venv/`、`data/`、`__pycache__/`、`.pytest_cache/`、`.env`、`.vefaas/`。部署前确认排除确实生效，避免密钥进包。
3. **运行时版本**：确认平台默认 Python 版本与本地兼容（课程记录时为 3.12）。
4. **网关**：`vefaas gateway list` 查可用网关；没有时由用户在控制台创建（课程记录：选 Serverless 网关、公网、与函数同地域；验证阶段可先关闭额外计费的可观测性开关，正式上线前再评估）。
5. **先配环境变量再首次发布**：`vefaas env set` 或 `vefaas env import`（导入后删除本地临时文件）。启动依赖的变量（如运行环境标识、数据库连接）缺失会导致启动即崩。只核对变量名是否存在，不输出值。
6. **部署**：`vefaas deploy --newApp <应用名> --gatewayName <网关名> --command "<启动命令>" --port 8000`。课程记录：首次部署不要同时设置最小实例数，否则可能因函数尚无版本而失败；需要时部署成功后再单独设置。
7. **前端（如单独部署）**：Next.js standalone 构建、复制 `.next/static`，构建时注入后端地址变量（rewrites 在构建时固化）；启动 `node server.js`。
8. **发布卡住**：出现“正在发布/滚动中”类报错时不要反复部署；先查发布记录状态，必要时按官方方式中止后重试。

## 上线后验证（替代“网址能打开就算成功”）

- 版本：确认线上运行的是本次 commit（版本接口、构建号或日志中的版本信息）。
- 核心业务：用测试账号完成一条真实输入到结果、再打开历史的流程。
- 权限：未登录被拒；错误凭证被拒；用户 A 不能访问用户 B 的数据（换 ID 直接请求）。
- 持久数据：写入测试数据 → 触发一次重新部署或实例重启 → 数据仍在。
- 恢复：在隔离环境用备份恢复一次并核对；未演练写“恢复未验证”。
- 观测：日志带 trace_id，可定位一次请求；错误告警可触达（如配置 Sentry）。
- 控制台状态可能滞后：以上述实测结果为准，而不是只看状态字段或首页能否打开。

## 常见报错对照（课程实战记录）

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| `uvicorn: command not found` | 实例 PATH 中无该命令 | 启动命令改为 `python -m uvicorn ...` |
| `Read-only file system` / `Permission denied` 写目录 | 除 `/tmp` 外只读，或缺少运行环境变量 | 数据改用托管数据库/对象存储；临时文件写 `/tmp`；先配好环境变量再发布 |
| 首次部署报函数未部署 | 首次部署同时设置了最小实例数 | 先部署，再单独设置 |
| 发布处于滚动状态无法再次发布 | 上次发布未结束 | 查状态、等待或按官方方式中止后重试 |
| 包体积几百 MB | `.venv`、`data` 未排除 | 检查 `.vefaasignore` |
| 子账号 `AccessDenied` | 缺少某服务的权限 | 按报错补最小权限，不直接给管理员 |
| 对象存储 `Bad Request` / 路径错误 | endpoint 或寻址方式不对 | 按官方 S3 兼容说明配置 endpoint、签名版本与 virtual-host 寻址（课程记录：北京区域为 `tos-s3-cn-beijing.volces.com`） |
| 隔段时间数据丢失 | 数据在 `/tmp` | 迁移到托管数据库；这不是靠预留实例能根治的问题 |
