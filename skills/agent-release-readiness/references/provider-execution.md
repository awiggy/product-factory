# 平台执行边界

此参考不保存易过期的厂商 CLI 命令。用户指定平台时按该平台执行；未指定且已有托管环境时优先复用。没有环境又涉及费用、公开访问或架构取舍时，提出少量方案让用户确定。

## 执行前核验

从当前官方文档或本机 CLI 帮助核对工具版本、认证方式、区域、运行时、构建/启动参数、网络入口、存储语义和配额。成本/计费、区域限制等结论必须有官方来源与核对日期；无法验证时不得当成事实保证。

如果环境已有适用的平台 Skill，可使用它处理准确的 API/CLI 细节；没有时不假设其存在。本 Skill 负责交付门槛，不取代平台工具，也不自动安装远程脚本。

## 操作前说清

- 对哪个账号/项目/环境做什么。
- 是否公开、是否会新增费用、是否覆盖当前版本或涉及数据迁移。
- 哪些用户授权已覆盖，哪些决策仍缺失。
- 如何判断成功、何时停止、失败如何恢复。

用户清晰授权且参数确定的正常部署步骤可执行，不为每条安全命令重复问确认；新增计费范围、破坏性数据操作或公开原本私有资源须单独获得对应授权。

密钥只经受控配置注入；展示变量名和是否已设置，不能输出值。权限不足时定位缺少的动作与资源范围，不直接建议管理员权限。避免命令行明文参数、shell 历史和构建日志泄漏。

不将“设置预留实例”“开启网关”“分离前后端”当跨平台规则。是否需要取决于目标平台与业务的实际约束；应用资源创建失败先查现状，不重复创建新资源碰运气。
