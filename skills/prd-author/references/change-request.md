# 变更模式：在原 PRD 上修订

用于两种情况：上线后根据 `factory/feedback.md` 开新版本；或下游阶段（蓝图、开发、QA）记录了需求层面的阻塞。

## 步骤

1. 读当前 `factory/prd.md`、上一版归档（`factory/history/vN/prd.md`，如有）、`factory/feedback.md` 或阻塞说明。
2. 列出变更项：新增 / 修改 / 删除 / 澄清，每项写来源（反馈编号、阻塞描述）和影响的 AC。
3. 在原文对应位置修改，不重写整份文档。删除的 AC 保留编号并标“已废弃（vN）”，新增 AC 用新编号，避免下游追踪混乱。
4. 更新文档头部版本与日期，在“变更记录”追加一行。
5. 判断影响面并写进审批摘要：是否需要重做蓝图、改数据结构、增加费用或外部平台。
6. 请用户签字（prd_signoff）。
